# Как агент публикует в Instagram и не делает лишнего

## Результат
Провести **один утверждённый материал** по официальному Instagram API: проверить файл и аккаунт, дождаться обработки, опубликовать один раз, открыть результат и вернуть владельцу ссылку. Пока владелец не подтвердил финальную карточку запуска, публикации быть не должно.

## Рабочий порядок
1. Откройте `ACCOUNT-READINESS.md`. Соберите ответы владельца, не додумывая пропуски.
2. Определите способ подключения. Для новой интеграции сначала проверьте Unified Login. У каждого маршрута свои токены, адрес API и разрешения: смешивать их нельзя.
3. Прочитайте через API ID и @username профессионального аккаунта. Сверьте их с ответом владельца.
4. Проверьте финальный файл, подпись, обложку и режим. После подтверждения их уже не правят исподтишка.
5. Выдайте Meta короткоживущую HTTPS-ссылку на файл. Саму подписанную ссылку в журнал не записывайте.
6. Запустите:
   `python instagram_publish_agent.py check --config config.json`
7. Затем создайте план командой `plan`. Покажите владельцу: аккаунт, тип публикации, хэши файлов, режим, ключевые флаги и `approval_hash`.
8. До подтверждения **именно этого hash** контейнер не создавайте.
9. После подтверждения создайте один контейнер и сразу сохраните его ID.
10. Проверяйте `status_code` с понятным таймаутом. К публикации переходите только при `FINISHED`.
11. Вызовите `media_publish` один раз.
12. Если связь оборвалась и ответ неясен, не нажимайте publish ещё раз. Зафиксируйте `PUBLISH_UNKNOWN`, проверьте тот же контейнер и последние публикации аккаунта.
13. Откройте опубликованный объект через API. Сверьте media ID, permalink, username, подпись, тип и время, насколько выбранный маршрут отдаёт эти поля.
14. Закройте временную ссылку и верните владельцу короткий отчёт без секретов.

## Чего агент не делает
- Не печатает и не сохраняет access token, app secret, cookies и подписанные ссылки.
- Не создаёт второй контейнер просто потому, что первый ответил медленно.
- Не меняет NORMAL на TRIAL или обратно без нового плана и подтверждения.
- Не выпускает обычный Reel, если Meta отклонила `trial_params`.
- Не работает с личным Instagram-аккаунтом.
- Не обещает, что App Review пройдёт, Trial доступен, а лимит равен красивой цифре из документации. Всё это проверяется на нужном приложении и аккаунте.
- Не делает live publish во время установки, тестов и демонстрации набора.

## Перед реальной публикацией
Все пункты должны быть выполнены одновременно:
- владелец подтвердил точный `approval_hash`;
- @username прочитан из API и совпал;
- проверены текущие лимиты контейнеров и публикаций;
- файл прошёл preflight;
- Meta может скачать временный HTTPS-файл, а его SHA-256 совпадает с оригиналом;
- `IG_ACCESS_TOKEN` лежит в секрет-хранилище;
- `IG_ENABLE_LIVE_PUBLISH=I_UNDERSTAND` включён только на время этого согласованного запуска.

## Если это карусель
Сначала создайте дочерний контейнер для каждого изображения или видео с `is_carousel_item=true`. Дождитесь готовности видео. Потом соберите один верхний контейнер `CAROUSEL` и опубликуйте уже его, один раз. Подпись и `is_ai_generated` относятся к верхнему контейнеру.

В официальных материалах Meta сейчас расходятся числа по максимальному количеству элементов. Поэтому не спорьте с документацией и не угадывайте: проверьте фактический предел на нужной версии API и аккаунте до боевого запуска.

## Если публикация стоит в календаре
Сам Instagram API не хранит ваш контент-план. Расписание живёт на вашем сервере. В назначенное время worker заново проверяет файл, hash, аккаунт и лимит, а затем проходит тот же маршрут. В базе храните UTC и исходный часовой пояс владельца.

## Что вернуть владельцу
Обычным русским, без технического тумана:
- что именно он подтвердил;
- что проверил агент;
- media ID и permalink;
- @username;
- NORMAL или TRIAL;
- время публикации;
- совпала ли подпись;
- закрыта ли временная ссылка;
- где лежит журнал;
- что осталось сделать вручную, если задача остановилась.
